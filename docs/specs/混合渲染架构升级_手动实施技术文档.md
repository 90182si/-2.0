> diff 规模：97 个文件，+6130 / -409 行。其中约 1500 行为新增测试与工具脚本，核心改动约 4600 行。

## 0. 总体架构变化图景

buildpin_version 的架构是：**引脚物理连接 + 表达式树 pull 求值 + 实例色直写**。
当前版本升级为：**CPU 端布尔 IR 求值 + GPU 端双纹理采样上色 + 事件变更定向传播**。

五条主线（可按顺序独立实施，每条实施完都能跑通旧行为）：

| 主线 | 名称 | 涉及子系统 | 一句话 |
|---|---|---|---|
| A | 纹理化渲染（T1） | render/、core/manager/、shader | 图集 region → styleTex，net 电平 → signalTex，实例 buffer 从"存 rect"改为"存 styleId/netId/flags" |
| B | IR 求值后端（T2） | circuit/ | 表达式树编译成扁平指令程序，getValue 查 slot 表，事件走变更定向求值 + push 回写 net |
| C | 存档与状态（Fix-3） | core/manager/、layers/、circuit/build/ | 元件自持状态显式入库、建筑 id 持久化、隧道 pairId 恢复 |
| D | m×n 多格建筑（T3） | res/、circuit/、layers/ | `SWBuildDefine.size` + occupancy 占位表 + 引脚边缘探测 |
| E | 增量渲染（R3/R4） | render/、layers/ | 信号变化只修补丁实例行，不回写电线 signal_state |

辅助线（可最后做或不做）：GDExtension 原生求值（Phase 4）、Verilog 导出器。二者都有开关，不影响 A~E。

> ⚠️ 注意 diff 中**没有** `circuit/sw_build_pin.gd` / `sw_build_pin_define.gd`：引脚定义结构（`cell_offset`、`pin_dir`、`wire_pin`）在 buildpin_version 已存在，本次未改。

## 1. 数据定义层（改动极小，先行）

### 1.1 `core/define/sw_define.gd`
- 新增常量 `MAX_RENDER_PARTS:int = 6`（单建筑渲染部件数上限，仅用于警告监控）。
- 新增枚举 `CircuitOp { OP_AND, OP_NAND, OP_PASS, OP_NOT, OP_LEAF }`——表达式树的**单态操作码**，供 EvalStruct 静态分派与 IR 编译器识别节点类型。
- `SWCircuitStruct` 新增字段 `op:int = -1`。`-1` = 走旧的 `optFunc` 闭包路径；`>=0` = 走静态分派。**这是向后兼容开关，必须保留**。
- 新增 `static func isSideways(dir:SW_Dir) -> bool`：LEFT/RIGHT 返回 true，供 m×n 旋转时 w/h 互换。

### 1.2 `com/sw_common.gd`
- 新增 `static func EnsureBuildIdCounterAtLeast(minId:int)`：存档加载后抬高全局 id 计数器，防新建建筑 id 冲突。
- `EvalStruct` 增加 `op != -1` 的 match 静态分派分支（OP_LEAF→EvalLeaf、OP_PASS→EvalArg(0)、OP_NOT→1-EvalArg(0)、OP_AND→EvalArgsAnd、OP_NAND→1-EvalArgsAnd），旧 `optFunc` 路径作为 `op == -1` 兜底保留。新增 `EvalArg / EvalLeaf / EvalArgsAnd` 三个辅助静态函数。
- 新增验收计数器 `evalStructCallCount`（IR 主路径下不应增长）。
- **线色表 `GetWireColor` 契约**：返回值 `Array[Color]`，`[0]`=LOW 色、`[1]`=HIGH 色，**绝对颜色**（不是乘算 tint）。当前值：电线B `[(0.066,0.26,0),(0.264,0.769,0)]`，默认 `[(0,0,0),(0.856,0.554,0.735)]`。加了 static `_wireColorCache` 按名字缓存——**改色表必须重启游戏**。
- 新增 `static func get_net_display_color(net:SWNet) -> Color`：HIGH 取 `[1]`，否则取 `[0]`；net 为 null 返回 TRANSPARENT。这是 signalTex 上色的唯一颜色来源。

### 1.3 `circuit/sw_net.gd`
`SWNet` 新增两个字段：
- `netId:int = -1`——全局唯一编号，signalTex 的 texel 索引。
- `paintedSignal:int = -999`——上次写入纹理的电平，`-999` 表示从未画过。用于避免重复上色。

## 2. GPU 纹理层（主线 A）

### 2.1 新文件 `render/sw_style_texture.gd`（class_name SWStyleTexture，RefCounted）
职责：把所有图集 region（Rect2）登记为 `1×N` RGBA32F 纹理，texel[i] = (x, y, w, h)，i 即 styleId。

- `static var instance`（全局单例，场景 `_init` 时建好）。
- `register_rect(r) -> int`：去重登记；键先经 `_norm_key` 把浮点 region 归一为整数 Rect2（浮点尾差不得分裂成两个 styleId）。
- `get_style_id(r) -> int`：未登记返回 **-1**（shader 侧品红哨兵的来源）。
- `build_texture()`：register 全部完成后一次性生成 image/texture。
- `build_from_registry(registry)`：遍历 Yard addon 的 `build_define_registry`，对每个 `SWBuildDefine` 登记 **5 类 region**：`atlasBuildBase`、`atlasIcon`、`atlasTextureOn`、`atlasTextureOff`、每个 `build_pin[i].wire_pin`。

> ⚠️ **已知坑（品红方块 bug 的根因）**：任何新增的 `.tres` 建筑若没进 `build_define_registry.tres`，它的 region 就不会登记 styleId，shader 里 `style_id < 0` 输出 `(1,0,1,0.5)` 品红半透明。**新增建筑 = 注册表必须同步加条目**（双向字典 `_uids_to_string_ids` 与 `_string_ids_to_uids` 都要加）。本次补登记了：时钟 `uid://yq74vaesbo45`、1bit寄存器 `uid://cgahjdxeo8yuu`（此前已在）等。

### 2.2 新文件 `core/manager/sw_signal_texture.gd`（class_name SWSignalTexture，RefCounted）
职责：`4096×16`（=65536 texel）RGBA32F 网格纹理，texel[netId] = net 显示颜色。

- 常量：`MAX_NETS = 65536`、`TEX_COLS = 4096`、`TEX_ROWS = MAX_NETS/TEX_COLS`。**不要用 1×65536 长条**——很多 GPU 最大边长 16384 会报纹理超限。
- `texel_pos(net_id) = Vector2i(net_id % TEX_COLS, net_id / TEX_COLS)`——**此公式必须与 shader 内换算逐字一致**。
- `set_net_color(id, c)`：越界静默忽略；只写 image + 标脏。
- `flush()`：脏时才 `texture.update(image)`，主循环每帧最多一次；`_update_count` 供测试断言。

### 2.3 `render/sw_grid_draw.gdshader` 重写
uniform：`srcImg` + 新增 `styleTex`、`signalTex`、`signalCols`(int, 默认 4096，须与 TEX_COLS 一致)。

fragment 逻辑契约：
1. `custom_data.x` = style_id(float)、`custom_data.y` = net_id(float)。
2. **判负必须用原始 float 符号**（`stylef < 0.0` / `netf >= 0.0`），不能先 `int()`——GSL 的 `int(-1.0+0.5)==0` 会绕过哨兵判定，这是曾经踩过的坑。
3. stylef<0 → 输出 `vec4(1,0,1,0.5)` 品红哨兵。
4. 否则 `texelFetch(styleTex, ivec2(sid,0), 0)` 取 rect，走原有 0.5px pad 防渗色采样。
5. netf>=0 → `color = texelFetch(signalTex, ivec2(nid % signalCols, nid / signalCols), 0) * COLOR`；否则 `color = COLOR`。
6. 混色链不变：`srcColor.rgb *= color.rgb; srcColor.a *= color.a`。**最终显示色 = 图集像素 × signalTex 色 × 实例 COLOR**，三层里只能有一层是"绝对色"，见 §9 坑 2。

### 2.4 `scene/sw_logic_scene.gd` 初始化时序（硬契约）
- `_init()`（autoload 的 _ready 之前）：创建 `SWStyleTexture`（先 `build_from_registry`）和 `SWSignalTexture`（`init()`）并赋给各自 `static var instance`。
- `_ready()`：才做 `SWObjectPool.InitSWChunkDataObject()` 对象池预热——池化依赖 `SwAtlas.current`，而它在 autoload `_ready` 里才赋值。**顺序颠倒会让池化节点拿到 null srcImg。**

### 2.5 `project.godot`
- autoload 与 main_scene 从 `uid://` 改回路径写法（`res://scene/sw_logic_scene.tscn` 等）。
- **删除了 `[rendering] rendering_device/driver.windows="d3d12"`**——回退默认 Vulkan/兼容驱动。实施时若你的项目特意要 d3d12 可保留旧行，但注意当前版本是删掉的。

## 3. 渲染实例层 `render/sw_multi_mesh_instance_2d.gd`（主线 A+E）

### 3.1 buffer 布局变更（核心）
每实例 float 数不变（use_colors 时 16，否则 12），但**尾部字段语义重定义**：

| 槽位(use_colors) | 旧 | 新 |
|---|---|---|
| +12..+15 | rect.x, y, w, h | **style_id, net_id, flags, 0.0** |

| 槽位(无 use_colors) | 旧 | 新 |
|---|---|---|
| +8..+11 | rect.x, y, w, h | **style_id, net_id, flags, 0.0** |

`flags`：bit0 = in_loop（环内红色警示由 shader/颜色侧处理），bit1 = HOLDING。
`_fill_instance` 签名改为 `(newBuffer, buffer_index, t, color, style_id:int, net_id:int, flags:int, use_colors)`。
parts 字典相应新增 `style_id / net_id / flags` 三个键（见 §5.3）。

### 3.2 uniform 设置抽取
`_ready()` 的逻辑抽成 `_resetShaderUniforms()`：设 `srcImg / styleTex / signalTex / signalCols` 四个 uniform，任一单例为 null 时 `push_warning`。**`reUse()`（对象池复用）必须重新调用它**，因为池化节点不会再触发 `_ready`。

### 3.3 R3.1 按建筑增量补丁
整块填充时记录 `_instRanges[build] = [起始实例号, 部件数]`，并记下 `_lastShowCount`、`_rangesBufferIndex`（双缓冲代次）。

- `drawMap(mapData, _flashDrawRegion=false, patchBuilds=[])` 第三参下发补丁条目，**元素一律为 `[建筑, parts快照, style补丁]`，后两者互斥**（在主线程备好，工作线程只读）：
  - style 补丁非空 `[style_id, bodyStart, bodyCount]` → 只覆写主体那几行的 style float（R3.4 快速通道）；
  - style 补丁为空 → parts 快照整行重写该建筑实例。
- `_can_patch()` 守护链（任一失败即回退整块重填并计入 `s_patch_bail[reason]`）：ByContent 模式 / 有补丁建筑 / 有区间记录 / 上次填充非空 / **缓冲代次一致**（`_pingPongIndex == _rangesBufferIndex`）/ 每个建筑有区间 / 不超容量 / parts 数一致 / style 区间落在登记行内。
- **线程安全两条铁律**：
  1. `_gridSizeTmp` 工作线程会读 → 只在 `patchBuilds` 为空（整块重绘）时由主线程刷新，补丁帧绝不写；
  2. 已发布的 parts 数组视为**只读**（copy-on-write，见 §5.3）。
- 整块重填请求进来时 `_rangesBufferIndex = -1` 使旧区间立即失效——防止"重填与后续补丁被信号量合并"时把补丁写进从没填过的 buffer。
- `reUse()` 里清 `_instRanges / _pendingPatchBuilds / _lastShowCount / _rangesBufferIndex`，并去掉了原来的 `while planIsRunning: pass` 忙等（改为 await 最多 10 帧 + 强制复位 + push_error）。
- 静态计数器：`s_draw_map_call_count / s_patch_hit_count / s_full_refill_count / s_patch_bail / s_patch_style_only_count`（验收增量是否真生效）。

### 3.4 Tiling 模式小改
Tiling 分支把 `drawRect` 与 styleId 提到循环外算一次（原来每实例重复查）。

## 4. 渲染组件 `circuit/build_compoent/sw_build_compoent_renderable.gd`

parts 数组的**构建顺序与内容**重写（这是 shader 采样和补丁定位的基础，顺序不能乱）：

1. **引脚 part**（先建）：每引脚 `{"rect", "offset"(旋转后 cell 偏移), "rotation", "color", "use_color", "net_id", "style_id", "flags"}`。
   - 有 net 时：`net_id = net.netId`，**`color` 必须为白色 `Color(1,1,1,1)`**——显示色由 signalTex 绝对驱动，烘焙 tint 会造成双重乘法（历史 bug，见 §9 坑 2）。
   - `in_loop` 红色覆盖分支在其后（use_color=true 强制红），行为不变。
2. **底座 part**：按 footprint `fp.y × fp.x` 逐格展开 `offset=Vector2i(i,j)`，net_id=-1。
3. **主体 part**：同样按 footprint 逐格展开；记录 `_bodyPartsStart = out.size()` 与 `_bodyPartsCount`（style 补丁的快速通道靠这个区间）。无 atlas 时 `_bodyPartsStart = -1`。
4. 末尾 `out.size() > MAX_RENDER_PARTS` 时 push_warning。

脏标记三态（缓存协议）：
- `_renderPartsDirty`：结构级失效 → 整份重建。`markRenderPartsDirty()` 同时清 `_bodyRectDirty/_bodyStylePending`。
- `_bodyRectDirty`：只换主体贴图（LED 亮灭）→ `markBodyRectDirty()`（结构未脏且存在 body 才受理）。
- `getStylePatch() -> Array`：结构未脏且 bodyRect 脏且有 body 时返回 `[new_style_id, _bodyPartsStart, _bodyPartsCount]` 并置 `_bodyStylePending = true`；否则返回 `[]`（调用方改发 parts 快照）。
- `getRenderParts()`：缓存命中但存在待补 body 时先 `_applyBodyRect()`（copy-on-write：duplicate 指针数组，只新建 body 那几项的字典）再返回。
- `isRenderPartsDirty() = _renderPartsDirty or _bodyRectDirty`；建筑层 `SWBuildItemDefine.isRenderPartsDirty()` 在组件未创建时返回 false（避免懒创建误判 dirty）。
- 新增 `var drawIndex:int = 0`（点击路径排序用，见 §7）。

## 5. m×n 多格建筑（主线 D）

### 5.1 定义与资源
- `res/sw_build_define.gd`：`@export var size:Vector2i = Vector2i(1,1)`（逻辑格尺寸，未旋转基准；缺省 1×1 完全向后兼容旧 .tres）。
- 新增三个 .tres：`2x2基地`（size 2×2，region 0,0/0,256 各 256×256）、`1x3横梁`（size 1×3，region (256,0)/(256,128) 128×128）、`3x3测试块`（size 3×3，region (768,0)/(768,128)）。**并同步登记进 `build_define_registry.tres` 双向字典**（§2.1 的坑）。

### 5.2 `circuit/build/sw_build_item_define.gd`
- `getFootprint() -> Vector2i`：`isSideways(rotation)` 时 w/h 互换。
- `getCoveredCells() -> Array`：锚点 `buildAxisPos` 起，`Vector2i(anchor.x + i*GRID.x, anchor.y + j*GRID.y)` 逐格。
- `getRotatedCellOffset(pin) -> Vector2i`：90°CW 递推公式——rot0:(x,y)；rot1:(y, s.x-1-x)；rot2:(s.x-1-x, s.y-1-y)；rot3:(s.y-1-y, x)。**与 renderable 的引脚 offset、边缘探测共用，只能有一份实现。**
- `in_loop` 改为带 setter 的属性：翻转时若 renderable 已存在则 `markRenderPartsDirty()`（环路红写在底座颜色里，视觉补丁覆盖不到，必须整份重建）。
- 新增 `getStateData() -> Dictionary` / `restoreStateData(data)` 虚基（返回 `{}` / pass），子类重写（§8.2）。
- 新增 `getDisplaySignal()`：先问电路组件 `getWireLevel()`（≥0 直接采用），否则回 `signal_state`（R4.1 电线显示/存档现取入口）。

### 5.3 `circuit/build/sw_build_manager.gd`
- 新增 `occupancy: Dictionary`（Vector2i axisPos → build.id）。
- `addBuild`：①所有 coveredCells 必须空闲（occId==0），任一冲突整体失败（**原子性**）；②写 occupancy；③锚点 chunk 登记；④**影子登记**——footprint 覆盖到的非锚点 chunk 把 build 加进 `chunk.shadowBuilds`（去重）。
- `delBuilds`：逐格清 occupancy（仅当 `occupancy[cell] == build.id` 才 erase，防误删），并从影子 chunk 移除引用。
- `getBuild(axisPos)`：优先查 occupancy O(1) 命中任意覆盖格（校验 `!bIsToBeRemoved()`），未命中回退旧单格逻辑。
- `getBuildsByRect`：判定从 `has_point(锚点)` 改为 **footprint 矩形与 region `intersects`**，加 `seen` 去重防跨 chunk 重复收集。
- `getRenderBuildsByChunkPos`：**只返回锚点建筑**（`chunk.notNullBuilds`），渲染用；`getBuildsByChunkPos` = 锚点 + shadowBuilds，查询/通知用。
- `clearAllBuilds`：同步清 `occupancy` 和 `buildStoreManager`（否则隧道按 id 查找会拿到上一会话的孤儿建筑）。

### 5.4 `circuit/build_compoent/sw_build_compoent_circuit.gd` 边缘探测
开关 `allowMulticell:bool = true`；生效条件 `allowMulticell and _isMultiCell() and not IsWireBuild`（电线永远 1×1 走旧路径）。
- `_isMultiCell()`：size.x>1 或 size.y>1。
- `_getPinByWorldDir(worldDir)`：遍历 build_pin，`wdir = posmod(pin.pin_dir + rotation, 4)` 匹配。
- `_getDirBuildFromPin(pin)`：引脚格 = 锚点 + rotatedOffset*GRID；邻格 = 引脚格 + dir_to_vec(worldDir)*GRID；`getBuild` 命中后还须验证**对方在该格有对应方向引脚**（`nextBuild.hasPinAt(neighborPos, antiDir)`，对方也是 m×n 时）且对方 antiDir 是端口、方向输入/输出互补。
- `hasPinAt(worldCell, worldDir)`：本建筑在指定世界格是否有朝 worldDir 的引脚。
- `getBuildIOConnectBuildArr` / `getNet` 各加多格分支（从引脚格出发查邻），旧路径原样保留为 fallback。

### 5.5 放置阴影（layers/hold）
`sw_hold_layer.gd`：`on_sel_tool_draw_data` 阴影从"1 条目/建筑"改为 `getCoveredCells()` 逐格 `addOneDrawBuildDefine(cell, shadow_define)`；`rotOnceHoldBuilds` 旋转后**重建**阴影列表（shadow 条数 ≠ main 条数，不能再按下标同步）。

## 6. 存档与加载（主线 C）——全部在 `layers/build/sw_build_layer.gd::load_save_data` + `core/manager/sw_save_manager.gd`

### 6.1 保存新增字段（save_builds）
- `signal_state` 改存 `getDisplaySignal()`（电线现取）。
- `tunnel_pair_id`：恢复持久化 `(build as SWBuildWireTunnel).pairId if build is SWBuildWireTunnel else -1`。
- `state`：`build.getStateData()`（元件自持状态）。
- `w` / `h`：定义尺寸（仅作向前兼容校验，加载端不据此重建 size——size 随 .tres）。

### 6.2 加载序列（顺序即契约，错一步电平就错一帧）
对每个建筑条目按序：
1. 定义资源按名字缓存（`defCache`，大存档省几万串拼+资源查询）；
2. `SWBuildCreator(pos, def, rot)` 创建；
3. **恢复 `build.id = saved_id`**（>0 才恢复）并记录 `maxRestoredId`；
4. 回填 `pairId`（隧道）；
5. **`restoreStateData(state)`——必须在 addBuild/updateBuildCircuit 之前**（pressed/curSig/qState 是求值入口直读的叶值，晚一步首遍就按默认电平算）；
6. `addBuild`；
7. 时钟类重新登记 `addClockBuild`（否则加载后 _process 驱动不到它）；
8. 全部完成后 `SwCommon.EnsureBuildIdCounterAtLeast(maxRestoredId)`。
9. `updateBuildCircuit(getAllBuilds())` → `flush_and_update_all_chunks()`。
10. **不要再调无参 `on_view_rect_changed()`**——它用尚未恢复的 color_rect 算视口会出错，随后 `apply_viewport` 会经 camera 触发正确的有参回调。

### 6.3 清空路径
`clear_all_builds`：额外清 `_pendingPlacedBuilds`、`clockBuildArr`，并调 `sw_circuit_control.resetNetIdCounter()` + `resetIR()`（全量清理/加载时 IR 后端整体作废重建）。

### 6.4 元件状态存取（circuit/build/*.gd）
- `SWBuildButton`：`{"pressed":bool}`；restore 走 `onPressed()` 一次搞定引脚电平+贴图+脏标记。
- `SWBuildClockSiggen`：`{"cur_sig":int}`；**时钟相位必须恢复**——onPressed 是"翻转"不是"设定"，不恢复则加载后第一拍整拍错开。
- `SWBuildRegister1Bit`：`{"q","last_clk","cur_clk","cur_d"}` 四个都要存——**只存 qState 不够**，沿检测历史丢了我方要么漏沿要么误锁存一拍；restore 后调 `buildStateChanged(qState)` 让贴图与 Q 一致。
- 组合元件（门/电线/灯泡）无自持状态，继承基类空实现即可。

## 7. IR 求值后端（主线 B）——本次 diff 的核心增量

三个新文件 + 编排层重写。总开关：`SWCircuitControl.useIR:bool`（关=完全走旧表达式树 pull 路径，行为与 buildpin_version 等价，可随时回退对比）。

### 7.1 新文件 `circuit/sw_bool_program.gd`（指令容器 + 求值机，GDScript 版）
opcode 常量（全局只这一套）：
```
OP_INPUT=0  读 net 电平入 slot
OP_LATCH=1  寄存器 Q 状态直读（叶）
OP_AND=2 / OP_NAND=3 / OP_NOT=4 / OP_PASS=5 / OP_CONST=6
OP_OUT=7    slot 值写回 net.curSignal（段求完执行）
OP_READ=8   状态驱动叶直读（按钮/开关 pressed、时钟 curSig）
```
数据数组（扁平，指令间用 slot 号链接）：`ops / a1 / a2 / dst_slot`、`slot_values`、`slot_uses`（slot→消费指令）、`leaf_insts`（build.id→OP_READ/OP_LATCH 指令下标，事件种子）、`slot_owner`（slot→建筑数组）、`segments`（circuitID→{start,end,iters}）、`input_meta/output_meta/latch_meta/read_meta`。
运行时簿记：`changed_slots`（本次事件电平真变化的 slot）、`dirty_nets`（被 OP_OUT 改写电平的 net，驱动 push 与上色）。
关键方法契约：
- `begin_event()`：清 changed_slots / dirty_nets。
- `collect_seeds(build)`：从 `leaf_insts[build.id]` 取叶子指令；**返回空 = 源建筑没 IR 入口（未编译/段被剪），调用方必须回退整段路径**。
- `evaluate_from(seeds)`：沿 use 表按拓扑序只跑受影响指令（Phase 2 变更定向）。
- `evaluate_range(start, end, iters)`：跑指令段，`MAX_SETTLE` 限迭代次数收敛。
- `mark_net_dirty(net)`：IR 之外改写 net 电平的入口（wired-AND 末位胜）登记给下一事件补读。
- `set_native_eval(bool)`：接 GDExtension（§11），扩展缺失时自动 `_native=null` 回落 GDScript。

### 7.2 新文件 `circuit/sw_bool_compiler.gd`（表达式树 → 扁平指令）
- **slot 全局递增、跨批次复用**；失活段只从 `segments` 剪除，**`slotMap`（`build.id*4+dir → slot`）本身从不自动剪除**——这是架构固有约束，后果见 §9 坑 3。
- `compile(affectedCircuits, circuits) -> SWBoolProgram`：遍历各电路建筑的 `pinExprMap` 表达式树，翻译为指令并登记 `slotMap[build.id*4+dir] = slot`（输入侧、输出侧都登记；NOT 同时登记输入/输出两个 key）。
- 叶子分派：引脚是状态驱动叶（`comp.getPinReadState(dir)` 返回 0/1）→ 生成 OP_READ/OP_LATCH；否则读 net → OP_INPUT。`getPinReadState` 返回 -1 表示非状态驱动。
- `static func detect_combinational_loops(circuits) -> Array`：**基于 noticeMap 的纯结构环检测，与 IR 无关，必须始终执行**（结果供 in_loop 红点渲染）。

### 7.3 组件层求值改造（`circuit/build_compoent/`）
基类 `sw_build_compoent_circuit.gd`：
- `getValue(dir)` 变为路由器：`_getIrSlotValue(dir)` 命中（≠-1）直返 slot 电平，否则 `_getValueTree(dir)`（原 pull 路径拆出的无副作用版）。
- `_getIrSlotValue(dir)`：经 `SWCircuitControl.current`（**新增 static var current**，供组件层无场景树访问，`_ready` 登记 / `_exit_tree` 释放，防测试多轮 boot 残留野引用）查 `slotMap[id*4+dir]` → `boolProgram.get_slot_value(slot)`。useIR 关 / 无程序 / 无 slot / 越界都返回 -1 走树。
- 新虚函数：`getPinReadState(dir) -> int`（基类返 -1）、`buildInputExprs()`（基类 pass）、`isSequential() -> bool`（基类 false）、`getWireLevel() -> int`（基类返 -1）、`appendDriverExprs(cirStruct, net)`（**统一的防环+时序屏障入口**：驱动是时序元件不判环直接取 Q 状态叶；驱动是组合元件且 `_buildingExpr` 中 → 真组合回边，双方 `in_loop=true`）。
- `getWireGroupBuilds` 邻接表改用 `control.getNeighborsCached(wBuild)`（同轮 find1 已算过，大存档实测省 >1s）。
- **`reCalSignals()` 基类改为只返回 `[buildRef]`**——不再把输入 net 上的电线建筑塞进通知列表（电线显示走 signalTex，塞进来只会让每帧多跑上千次必然落空的 dirty 检查）。

各子类：
- **source（开关/按钮）**：`op = OP_PASS`；getValue 在 useIR 时只返回值不写 net（push 阶段统一处理）；树路径保留主动刷 net+电线传播；重写 `getPinReadState` 直读 `pressed`。
- **clock_siggen**：同上，`getPinReadState` 直读 `curSig`（仅当 dir==rotation）。
- **register**：`isSequential()=true`。表达式构建拆两遍——`getBuildExpr()` 只建 Q 自源叶（`_buildQExpr`，OP_PASS）；**`buildInputExprs()` 在根层级第二遍单独展开 CLK/D 输入锥**（`getCircuit` 里第一遍 DFS 全部完成后统一调用）。若在 DFS 内连带展开输入锥，从 Q 侧进入的外层组合元件会被反向递归命中，**把合法时序反馈误判为组合环（in_loop 误标红）**——这是硬时序契约。getValue：Q 方向**两种模式下都执行边沿检测**（qState 是时序唯一真相），保持原顺序：先用上一拍 curClk/curD 判沿再刷新采样值；CLK/D 输入走 slot 直读；重写 `getPinReadState`（Q 方向直读 qState）。
- **led**：`getBuildExpr` 重写为统一入口——遍历 net 的驱动，**驱动是电线时对电线各 net 调 appendDriverExprs 桥接**；无驱动源时**不创建表达式**（悬空=低电平，且必须 `op=OP_AND` 才挂进 pinExprMap）。getValue：slot 命中直读；树路径仅有效电平（≠NONE）才写回 net（防 NONE 覆盖驱动源已写入的信号）。
- **not**：`getBuildExpr` 恢复 `_buildingExpr` 防环标志，改用 `appendDriverExprs`，`op = OP_NAND`。getValue 重写：表达式挂在**输入方向**键上、NAND 已含取反，**不可二次取反**（旧代码在输出侧再翻一次是历史错误）；树路径结果写**输出方向** net 并向下游电线传播。
- **wire / wire_cross**：`getNet` 复用邻接缓存遍历；`reCalSignals` 只返回自身；重写 `getWireLevel()`（电线=所在 net 的 curSignal，未联网 NONE；交叉电线取纵向 net，无则横向）。**R4.1：电线 signal_state 不再逐帧回写**，全工程无人读它，显示/存档走 getDisplaySignal。

### 7.4 编排层 `circuit/sw_cirucit_control.gd`
新增成员：`static var current`、`boolProgram`、`useIR/useChangeDirected/useNativeEval` 三开关、`_compiler`（跨批次复用）、`slotMap`（直接引用编译器内部表）、`_netIdCounter`、tick 簿记（`_tickMode/_tickPaintNets/_tickPaintBuilds`）。

**netId 分配（T2.2）**：`_assignNetIds(builds)` 在 `updateBuildCircuit` 中 createNets 之后、resetEmptyWireNet 之前调用；遍历 pinNetMap 出现过的 SWNet 递增编号（wireGroup 共享 net 对象，按对象引用去重）；计数器**累积递增不重置**（防增量更新时其他 net 编号漂移），只在 `clearAllBuilds`/加载时 `resetNetIdCounter()`；超过 MAX_NETS 打警告并保持 -1（绝不越界写纹理）。

**updateBuildCircuit 尾部新增（T2.4/T2.5）**：
1. 收集受影响电路 → `detect_combinational_loops`（无条件）→ 命中者 `in_loop = true`；
2. useIR 时：复用/新建 `_compiler` → `compile` → `set_native_eval` → **立即全量 `evaluate()`** 使 slot 与世界一致 → `_pushDriverNets`（把 OP_OUT 写回的 net 传播到电线视觉）→ 对 affectBuilds2 中**非时序组件**补跑一次 `reCalSignals()` 重绘显示（createCircuit 里那次 Pass B 跑在编译之前，读的是上一份程序；时序元件除外——多跑会重复消费路上那个上升沿）。**LED 滞后一拍的历史 bug 就靠这一步修**。

**buildSignalChanged（事件路径）**：
- Phase 2 快路径：`begin_event → collect_seeds(build)`，非空则 `evaluate_from(seeds)` → `_collect_changed_builds`（changed_slots 反查 slot_owner，类型口径 LED/寄存器/NOT，排除事件源自身）→ 逐个 `reCalSignals` → `_pushDirtyNets(dirty_nets)` → 上色。seeds 空回退整段路径。
- 回退路径拆两 Pass：**Pass A 纯结构 BFS**（只靠 noticeMap 展开，不调 reCalSignals，且 NOT 也必须入 BFS——IR 路径靠它触发 push 重算）；**段求值**（按 circuitID 去重 `evaluate_range`）；**Pass B** 只对 slot 值真变化的建筑调 reCalSignals（树模式回退到 BFS 闭包）。
- `_pushDirtyNets/_pushDriverNets/_applyNetDriver`：wired-AND 语义**末位驱动者胜**（从 drivers 末位向前找第一个命中 slot 的驱动者）；`net.curSignal = sig` **无条件写回**（OP_OUT 已预写导致 `!=` 守卫恒假是历史 bug）；写完 `mark_net_dirty` 登记给下一事件补读。多驱（≥2 driver）必须立即写回——同拍后续事件的 OP_INPUT 要读它，不能推到 endTick。

**拍模式合并上色（T2.8）**：`beginTick/endTick` 包裹时钟 tick 循环——一拍内多时钟各自触发事件，signalTex 上色合并到拍尾按 net 去重；**段求值/Pass B/push 仍逐事件跑**（寄存器边沿检测依赖每次采样）。

**上色收敛点**：`_paintVisuals(dirty_nets, paintBuilds)` → `_paintNet`：netId 非法跳过、按 netId 去重、**`curSignal != paintedSignal` 才写纹理并更新 paintedSignal**（防止推错状态）。`SWSignalTexture.instance == null` 时整体跳过。

**删除契约两条血泪教训**（历史 bug 详见 §9 坑 1/3）：
1. 所有删除入口（Delete 键 `_do_delete_selected` / 剪切 `_do_cut` / 右键擦除 `holdRemoveBuilds`）**必须先 `setBuildsState(builds, TO_BE_REMOVED)` 再 `delBuilds`**——`find1/getNet/getDirBuild` 全靠 `bIsToBeRemoved()` 把已删建筑排除在重建集合外，漏标时 deleted 电线按旧格位继续桥接邻居。
2. `clearBuildsCircuitState` 中**必须为受影响建筑 `slotMap.erase(build.id*4+dir)`（dir 0..3）**再重建——slotMap 永不自动剪除，失表达式的建筑若不清入口，getValue 会经 `_getIrSlotValue` 命中旧 slot 的陈旧电平（删了电线下游仍亮）。受影响建筑本轮都会重编译重新登记，**先清后铺即可自愈**。

## 9. 已知坑与历史 bug 复盘（手动实施时逐条对照自检）

1. **删电线下游仍收信号**（双层根因）：次因=`_do_delete_selected/_do_cut` 漏标 TO_BE_REMOVED；主因=slotMap 陈旧条目使 `_getIrSlotValue` 命中旧 HIGH slot、永不回退树求值。两条契约见 §7.4。**回归测试必须三条删除路径全覆盖**——只修一条时测试仍全红，据此才挖出主因。
2. **电线颜色双乘**：最终色 = 图集 × signalTex × 实例 COLOR 三层相乘，signalTex 已写绝对色（GetWireColor 的 [0]/[1]），端子烘焙 tint 必须为白色；否则 LOW 显示 [0]²、HIGH 显示 [0]×[1]，与线色表对不上。
3. **slotMap 从不剪除**：架构固有约束（§7.2），任何"建筑失去表达式"的路径都要显式 `erase(id*4+dir)`。
4. **品红方块**：styleTex 未登记 region 的哨兵色；新增 .tres 必须同步进 `build_define_registry.tres` 双向字典（手写 UID 若 `ResourceLoader.exists` 失败，需在编辑器 YARD 面板重扫）。
5. **shader float→int 截断**：`int(-1.0+0.5)==0` 绕过负数哨兵，判 -1 必须用原始 float 符号（style_id 与 net_id 两处）。
6. **`_gridSizeTmp` 线程竞争**：只在整块重绘（patchBuilds 空）时由主线程刷新。
7. **时钟相位/寄存器沿历史必须入档**：只存 qState 不够，lastClk/curClk 丢了加载后误锁存。
8. **restoreStateData 必须早于 addBuild/updateBuildCircuit**。
9. **时序元件表达式两遍构建时序**（register）：DFS 内展开输入锥 → 合法反馈误判组合环。
10. **LED 加载/编辑后滞后一拍**：createCircuit 的 Pass B 跑在编译前，编译后须对非时序组件补跑一次 reCalSignals。
11. **`_wireColorCache`/线色表是 static**：改色表需重启游戏。
12. **NOT 不可二次取反**：表达式挂输入方向、NAND 已含取反。
13. **池化 reUse**：必须重设 shader uniform 并作废区间记录。
14. **无参 `on_view_rect_changed()` 已从加载路径删除**：用未恢复的 color_rect 计算视口会出错。
15. **1×65536 纹理条**：GPU 边长上限 16384 会爆，signalTex 必须 2D 网格排布（4096×16）。
16. **`clearAllBuilds` 必须连 `buildStoreManager` 一起清**：隧道 pairId 按 id 查找，残留会返回上一会话孤儿建筑。
